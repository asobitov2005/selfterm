# SelfTerm Electron vs Rust + Tauri: Linux release benchmark

Measured on 2026-09-27, Ubuntu 24.04 x86_64/X11, AMD Ryzen 7 5700U with Radeon Graphics. Electron 33.4.11, Tauri 2.12.0, WebKitGTK 2.52.6. Both apps use the same React production frontend from commit `043beea`. This compares the current Electron implementation with the partial Rust/Tauri migration, not a UI written entirely in Rust.

## Results

Values below are medians across three runs. RAM values are medians within each 30-second interval, then medians across runs.

| Metric | Electron | Rust + Tauri |
| --- | ---: | ---: |
| Deb package (MiB) | 101.28 | 12.74 |
| Installed app files (MiB) | 346.60 | 25.53 |
| RAM PSS (MiB) | 288.26 | 200.30 |
| RAM private (MiB) | 179.86 | 154.07 |
| RAM RSS sum (MiB) | 645.94 | 415.82 |
| Idle CPU (% of one core) | 0.37 | 0.16 |
| Startup CPU time (seconds) | 1.14 | 1.16 |

Tauri used **30.5% less PSS RAM** and its deb package was **87.4% smaller** in this test. Startup CPU time was approximately equal. Both apps consumed little CPU while idle.

Tauri idle CPU varied from 0.10% to 0.84%, compared with Electron 0.30% to 0.43%. The third Tauri run was higher; its cause was not diagnosed. These small idle values do not establish a general CPU-performance advantage.

## Method and limits

- Native release builds: `npm --prefix apps/client run tauri -- build --bundles deb` and `npx electron-builder --linux deb --publish never`.
- Packaged Electron executable and release Tauri executable; embedded production assets, no Vite server or DevTools.
- Separate temporary profiles, zero hosts, zero sessions, matching appearance settings and confirmed 1280×820 X11 client windows.
- One discarded preparation/warm-up run per app. Existing initialized profiles were reused for measured runs; these are warm starts, not fresh-install or cold-disk starts.
- Three measured runs per app, alternating order. Each run waits 15 seconds, then samples RAM every second for 30 seconds. Builds finished before measurements began.
- Include the application and all descendant processes. CPU is user + system CPU time from `/proc`, with 100% representing one logical core. Startup CPU time is cumulative sampled process CPU time during the first 15 seconds, **not wall-clock launch latency**. Very short-lived processes between samples can be missed.
- PSS divides shared mapped pages proportionally. RSS sums shared pages repeatedly. Private memory excludes shared pages. Kernel/GPU allocations and external OS daemons are not measured.
- Installed size is deb `Installed-Size` metadata. OS-provided shared libraries are excluded; Tauri uses system WebKitGTK, while Electron bundles Chromium. These are app payload sizes, not the complete dependency download on a clean OS.
- SSH/SFTP/RDP/VNC workloads are not covered. The Rust client currently lacks complete protocol adapters, so this is an idle Hosts-screen benchmark and does not establish feature parity or performance under load.
- Only this Linux computer was tested. Windows, macOS, Android and iOS results remain unmeasured.
- Electron sandbox helper permissions were configured as for an installed package for the measured runs; no `--no-sandbox` flag was used. Original extracted-file ownership and permissions were restored afterwards. Synthetic benchmark credential-store entries were removed.

## Reproduce

The Python harness requires Python 3 and an X11 desktop session with readable `/proc/*/smaps_rollup`. The native app also needs access to the desktop OS credential store. Run after compiling both apps.

```sh
python3 scripts/benchmarks/linux_idle.py \
  --electron release/linux-unpacked/selfterm-linux \
  --tauri /tmp/selfterm-rust-target/release/selfterm-client \
  --output docs/rust-migration/benchmarks/linux-2026-09-27.json
```

Use a properly configured Electron sandbox helper or installed package. The harness prints its temporary profile directory in the JSON result. Remove only the synthetic key belonging to that directory using the checked-in native helper:

```sh
CARGO_TARGET_DIR=/tmp/selfterm-rust-target cargo build -p selfterm-client \
  --release --features tauri/custom-protocol --example benchmark_cleanup
/tmp/selfterm-rust-target/release/examples/benchmark_cleanup /tmp/selfterm-benchmark-EXAMPLE
```

The cleanup helper rejects paths outside a direct temporary `selfterm-benchmark-*` directory. [Raw samples and metadata](linux-2026-09-27.json) are checked in with this report.
